RoboSense ObjectType 분류 조사 결과

대상: 횡단보도 보행자 검출 / web_hmi 오브젝트 표시 · 브랜치 siheung_dev · 조사일 2026-07-21 · SDK ~/SDK_20220818
⚠ 핵심 결론
ObjectType enum 정의는 정확하다(SDK 확인). 문제는 RoboSense AI 인지 모델이 차량을 BIC(자전거)로 오분류하는 것이다. 그 결과 type∈{2,3}=보행자 매핑을 쓰면 web_hmi 가 자차 좌/우 차량을 "사람"으로 표시했다. enum 을 바꿀 게 아니라, 라벨을 신뢰할 수 없으므로 크기(size) 기반 보조 판정 또는 SDK 의 class 보정(type fusion) 활성화가 필요하다.

1. 증상

  • web_hmi 지도에서 자차 바로 좌/우의 차량이 "pedestrian(사람)"으로 표시됨.
  • bag 2026-07-21-16-53-32_..._0.bag 녹화값(/hmi/threejs/tracks·/hmi/objects)에서 좌/우 객체 대부분 type=pedestrian 으로 기록 — 실제로는 차량.

2. ObjectType enum — SDK 에서 확인 (정의는 정확)

바이너리 SDK ~/SDK_20220818 에서 소스·라이브러리 심볼 모두 동일한 enum 확인:

출처내용
release/libs/perception/include/rs_perception/common/external/basic_type/object_type.henum class ObjectType 정의
release/rs_tool/.../proto_msg/Proto_msg.Percept.pb.henum ObjectType (OBJECT_* 접두, 동일 값)
librs_perception_lidar_ai_detection.so (심볼)kObjectType2NameMap / kObjectTypeName2TypeMap — 바이너리도 동일 enum 사용
enum class ObjectType {
    UNKNOW        = 0,
    CONE          = 1,
    PED           = 2,   // 보행자
    BIC           = 3,   // "자전거" (라벨) — 그러나 실측은 차량 크기
    CAR           = 4,
    TRUCK_BUS     = 5,
    ULTRA_VEHICLE = 6,
    MAX_OBJ_TYPE_NUM = 7,
};
사용자가 코드에서 확인한 enum 과 100% 일치 → enum 매핑 오류 아님.

3. 실데이터 분석 — type 라벨 ↔ 실제 크기 불일치

/track_Multi_RS 객체의 status(=ObjectType) 별 bounding box 최대변(size) 분포 (bag 20260508 · 2026-07-21):

typeenum 라벨실측 최대변판정
1CONE~0.72 m일치(콘)
2PED~1.85 m일치(보행자)
3BIC (자전거)~4.93 m (100% >2.5m)❌ 실제 차량 크기
4CAR~10 m트럭/버스급
6ULTRA_VEHICLE~0.56 m매우 작음

→ 1(콘)·2(보행자)만 이름값과 맞고, type 3(BIC)은 자전거가 아니라 5m 차량. AI 모델이 차량을 BIC 로 예측(오분류).

자차 좌/우 오브젝트 (bag 2026-07-21-16-53-32, 21프레임)

위치원시 status(=ObjectType)녹화 HMI 표시
좌측 (y>0)BIC(3) 213 · CONE(1) 8 · PED(2) 1대부분 pedestrian (오표시)
우측 (y<0)BIC(3) 72 (전부)전부 pedestrian (오표시)

좌/우 BIC(3) 객체 = 전부 size 5.0m = 차량. 녹화 시점 코드가 {2,3}→pedestrian 이라 화면에 사람으로 떴다.

5. 원인

enum(정의)은 정확 · RoboSense AI 모델이 5m 차량을 BIC(3)로 오분류(모델 예측 정확도 문제). 모델은 암호화돼 있어 바이너리로 고칠 수 없음.

7. 권장

  1. SDK class 보정 활성화: rs_lidar.yaml 의 enable_type_fusion: true 로 켜고 재기동 → 차량이 CAR(4) 로 잡히는지 실측. (RoboSense 인지 config 측, 실차/재생 테스트 필요)
  2. 크기 기반 보조 판정(확실): type 라벨을 못 믿으므로, 보행자 판정에 size 조건 추가 — 예: BIC(3)라도 max(size_x,size_y) > 2.5m 이면 차량 취급. (앞서 제거한 크기 게이트가 정확히 이 목적)
  3. PED(2)만 신뢰: PED(2)는 크기 1.8m 로 이름값 일치 확인됨 → 확실한 보행자 후보는 type==2.
