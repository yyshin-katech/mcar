BSM partII 주행예정 링크 시퀀스 확장 규격

J2735 BasicSafetyMessage 사설 확장 — 차량이 곧 지날 링크 ID 순서열 전송

버전 v1 메시지 J2735 BSM (messageId 20) 확장 위치 partII partII_Id 63 payload UTF-8 JSON 인코딩 UPER (MessageFrame) 작성일 2026-06-11
주의 — 사설(non-standard) 확장. 본 규격은 SAE J2735 표준이 정의한 컨텐츠가 아니라 시흥 V2N 폐쇄망 내부에서만 통용되는 사설 확장이다. 표준 J2735 수신기는 이 partII 블록을 무시하므로 정상 동작에는 영향이 없으나, 본 데이터를 해석하려면 수신측이 partII_Id = 63 과 아래 JSON 포맷을 사전에 알아야 한다.

1. 목적

자율주행 차량이 현재 주행 중인 링크와 곧 지나갈 링크들의 ID 순서열을 10 Hz BSM 에 실어 관제(V2N 센터)로 전송한다. 링크 ID 는 시흥 HD맵(senario) link_*.mat 의 LINK_ID_string 값(예: A222BF785106)을 사용한다.

2. 메시지 위치 (계층)

V2N 컨테이너(16B 헤더, fid=0xFF10, psid=0x00014082)
 └─ UPER MessageFrame (messageId = 20, BSM)
    └─ BasicSafetyMessage
       ├─ coreData ………………… (기존: 위치/속도/방위/가속/조향/브레이크/크기)
       └─ partII SEQUENCE OF PartIIcontent
            └─ [0] { partII_Id = 63, partII_Value = OpenType(raw) = JSON }

기존 coreData 는 그대로 유지된다. 본 확장은 partII 리스트에 원소 1개를 추가할 뿐이다.

3. partII 컨테이너

필드값 / 타입설명
partII_Id63 (INTEGER 0..63) 사설 식별자. 표준 0/1/2 (vehicleSafetyExt / specialVehicleExt / supplementalVehicleExt) 회피.
partII_ValueOpenType, type = NULL raw octet string 모드. 내용 = UTF-8 JSON 바이트(아래 §4). UPER 상 length-prefix + 옥텟.
partII_Id 범위. J2735 PartII-Id ::= INTEGER (0..63). 64 이상은 UPER 인코딩이 실패한다. 본 규격은 범위 상단의 미할당 값 63 을 예약한다.

4. payload — JSON 스키마 (v1)

partII_Value 의 octet string 내용은 다음 UTF-8 JSON 객체이다.

키타입필수설명
vintegerY포맷 버전. 현재 1.
linksarray<string>Y 주행 링크 ID 순서열. links[0] = 현재 링크, 이후 = 곧 지날 링크 (NEXT_LINK_ID 체인 순). 각 원소는 mat LINK_ID_string (예 "A222BF785106").
nintegerY links 원소 개수. 1 ≤ n ≤ route_lookahead (기본 cap 10).

예시

{"v":1,"links":["A222BF785057","A222BF785082","A222BF795015",
                "A222BF795016","A222BF795116","A222BF795100",
                "A222BF795109","A222BF795110","A222BF795103",
                "A222BF795179"],"n":10}

위 예시는 현재 링크 A222BF785057 (mat LINK_ID 417) 에서 NEXT_LINK_ID 체인을 10개까지 따라간 결과이다.

LINK_ID_string 포맷

예: A222BF785106 — 시흥 HD맵 링크 문자열 식별자. 숫자형 LINK_ID(예 5106 계열) 와 1:1 대응되며, 본 규격은 항상 문자열형을 싣는다.

5. 와이어 인코딩

코덱

래핑

V2N 컨테이너

참고 크기

6. 수신측 디코딩 절차

  1. V2N 16B 헤더 제거 → 잔여 = UPER MessageFrame.
  2. MessageFrame UPER 디코드 → messageId == 20 확인, value = BasicSafetyMessage.
  3. partII 리스트 순회 → partII_Id == 63 원소 탐색.
  4. 해당 partII_Value 의 octet string(raw)을 UTF-8 로 해석 → JSON 파싱.
  5. v 확인 후 links[] 사용. (TIM rx 노드의 jsonCandidatesFromOpenType() 로직 재사용 가능.)
round-trip 검증 완료. partII_Id=63 + JSON 부착 → MessageFrame UPER 인코딩(218B) → 디코딩 시 partII_Id=63, octet_string 이 원본 JSON 과 바이트 단위 일치 (PASS).

8. 제약 / 한계

  • 사설 확장 — 시흥 V2N 폐쇄망 + 사전 합의 수신측에서만 해석. 표준 수신기는 무시.
  • 단일 NEXT_LINK_ID 체인만 추적 — 분기/차선변경 등 다중 경로는 미표현. next=0 이면 종료.
  • 10 Hz 브로드캐스트 — 링크열 변동이 없으면 매 프레임 동일 payload 재전송. 개수 cap 으로 크기 관리.
  • 링크 ID 어휘는 senario HD맵에 종속 — 맵 갱신 시 CSV 재생성 필요.
